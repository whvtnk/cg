# 11-апта — Текстура

Құрастыру және іске қосу:

```bash
cmake -S . -B build && cmake --build build && ./build/cg
./build/cg --shots      # screenshots/ ішіндегі барлық скриншотты қайта түсіреді
```

Терминалда:

```
.../assets/container.png  512x512  арна: 3
.../assets/awesomeface.png  512x512  арна: 4
```

## Не істелді

- `external/stb/stb_image.h` (v2.30), `#define STB_IMAGE_IMPLEMENTATION` — `#include`-тан бұрын.
  Ескерту: `master` бұтағындағы ең жаңа нұсқа (2026-11) `stbi_load(..., 0)` шақыруын
  `bad req_comp` қатесімен қабылдамайды, сондықтан тұрақты 013ac3b коммиті алынды.
- `assets/container.png` (512×512, 3 арна), `ASSET_DIR` — CMake арқылы абсолют жол.
- `vertices[]`: позициялар мен CCW реті 10-аптадан өзгерген жоқ, үш түс саны екі UV санына ауысты.
  Әр жақтың UV-і сырттан қарағанда сурет айналық болмайтындай таңдалды.
- Екі `glVertexAttribPointer`-де де stride = 5, UV атрибуты 2 компонентті.
- `loadTexture()`: `glGenTextures` → `glBindTexture` → 4 × `glTexParameteri` → `stbi_load` →
  `fmt` арна санынан → `glTexImage2D` → `glGenerateMipmap` (кейін!) → `stbi_image_free`.
- Шейдерлер: `vec2 aTexCoord` → `vTexCoord`, `sampler2D ourTexture`, `texture()` (`texture2D` емес).
- Render циклінде `glActiveTexture(GL_TEXTURE0)` + `glBindTexture`, `glUniform1i(ourTexture, 0)`.
- 3-тапсырма үшін `cubePositions[]`-ке z ≈ −40 маңында 6 куб қосылды.
- Барлық тапсырма бір `main.cpp`-да, пернелермен ауыстырылады.

## 1-тапсырма — орау режимдері

UV ×2 болғанда координаттар 0…2 аралығында, яғни жақтың үш ширегі [0, 1]-ден тыс.

| Режим | Не болады | Қай жағдайға қолайлы |
|-------|-----------|----------------------|
| GL_REPEAT | сурет 2×2 қайталанады | қабырға, еден, шөп, кірпіш — шеттері бір-біріне сәйкес келетін (tileable) текстуралар; ағып жатқан су (Қ3) |
| GL_MIRRORED_REPEAT | әр келесі көшірме айнадай аударылады | шеттері сәйкес келмейтін, бірақ симметриясы маңызды емес табиғи текстуралар (тас, құм, бұлт) — тігіс жоқ |
| GL_CLAMP_TO_EDGE | шеткі пиксель созылады | бір рет салынатын сурет: UI, жапсырма (decal), skybox, шрифт атласы — шетте бөгде түс «ағып» кірмейді |
| GL_CLAMP_TO_BORDER | [0, 1]-ден тыс — шекара түсі (қызыл) | бір рет салынатын сурет, сыртқы аймағы мөлдір/белгілі түс болуы керек жерде: көлеңке картасы (сырты = «көлеңке жоқ»), проекцияланатын текстура |

**REPEAT пен MIRRORED_REPEAT айырмашылығы** u = 1 және v = 1 сызықтарында (жақтың ортасында) көрінеді.
REPEAT-та картинканың оң шеті келесі көшірменің сол шетімен қатар тұрады — шеттер әртүрлі болса, тігіс
байқалады (container.png-де ортада екі жақтау қатар тұрып, қалың сызық шығады). MIRRORED_REPEAT-та шекарада
шет өзінің айнадағы көшірмесімен түйіседі, сондықтан пиксельдер үзіліссіз жалғасады — тігіс жоқ, бірақ
симметрия көзге түседі.

## 2-тапсырма — NEAREST және LINEAR

UV ×0.1 → бір жаққа 512 · 0.1 ≈ 51 тексель созылады, fov 8° кезінде бір тексель экранда ≈ 15 пиксель.
NEAREST ең жақын бір текселді алады — айқын шаршылар; LINEAR төрт көрші текселді қашықтыққа қарай
араластырады — жұмсақ, бұлыңғыр ауысу.

- **Пиксель-арт ойын** — GL_NEAREST: суретші әр пиксельді қолмен салған, үлкейткенде шаршылар анық қалуы
  керек; LINEAR оларды бұлыңғыр етіп, стилді бұзады.
- **Фотореалистік ойын** — GL_LINEAR (MIN-ге mipmap-пен трилинейлік, плюс анизотропия): жақын келгенде
  тексельдер көрінбейді, бет тегіс көрінеді.

## 3-тапсырма — mipmap

Бір сөйлеммен: mipmap-сыз (08) алыстағы кубтар мен еден шулы, муар жолақтар шығады және камера қозғалғанда
жыпылықтайды, mipmap-пен (09) олар біркелкі, сәл бұлыңғыр және тұрақты.

**Бір фрагментке неше тексель сәйкес келеді.** 512×512 текстурасы бар жақ экранда 20×20 пиксель:

- бір осьте: 512 / 20 = 25.6 тексель бір пиксельге;
- ауданы бойынша: 25.6² ≈ **655 тексель бір фрагментке**.

Mipmap-сыз GL_LINEAR осы 655-тің тек 4-еуін оқиды, қалғаны еленбейді. Қай 4 тексель түсетіні камера сәл
жылжығанда кездейсоқ өзгереді — сондықтан жыпылықтау.

Mipmap деңгейлері: 512, 256, 128, 64, 32, 16, … Қажетті деңгей log₂(25.6) ≈ 4.68, яғни 4-деңгей (32×32,
1.6 тексель/пиксель) мен 5-деңгей (16×16, 0.8 тексель/пиксель) арасы. Трилинейлік сүзгі осы екі деңгейдің
әрқайсысынан 4 тексельден алып, араластырады. Бір фрагментке ~1–2.5 тексель келеді, ал әр тексель
алдын ала орташаланған (бастапқы суреттің 16×16 немесе 32×32 блогы) — ақпарат жоғалмайды, жыпылықтау жоқ.

## 4-тапсырма — қара куб

`glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR_MIPMAP_LINEAR)` нақты нәтижесі:

```
MAG = GL_LINEAR_MIPMAP_LINEAR -> glGetError() = 0x0500 (GL_INVALID_ENUM), MAG фактически = 0x2601
```

OpenGL спецификациясы бойынша MAG тек GL_NEAREST не GL_LINEAR болады; басқа мән `GL_INVALID_ENUM` береді
және **параметр өзгермейді** (0x2601 = GL_LINEAR қалды). Сондықтан Mesa-да куб қара болмады
(10b-bad-mag.png — сурет қалыпты). Кейбір ескі/спецификациядан ауытқитын драйверлерде ғана қара болуы мүмкін.

Шын қара куб (10-black-cube.png) — сол «mipmap» тобындағы басқа қате: MIN = GL_LINEAR_MIPMAP_LINEAR, бірақ
`glGenerateMipmap` шақырылмаған (`K` пернесі). Текстура «толық емес» (incomplete) болады, ал толық емес
текстурадан оқу (0, 0, 0, 1) береді. Мұнда `glGetError()` ешқандай қате қайтармайды.

**Мұндай қатені қалай табар едім:**

- `glGetError()` MAG жағдайында **көмектеседі** — әр `glTexParameteri`-ден кейін тексерсе, `GL_INVALID_ENUM`
  шығады (жоғарыдағы шығару). Бірақ ол тек соңғы қатенің кодын береді, қай жолда екенін айтпайды, сондықтан
  күдікті шақырулардың арасына қою керек. Толық емес текстура жағдайында көмектеспейді — бұл қате емес.
- `glGetTexParameteriv` арқылы параметрдің шын мәнін оқу.
- OpenGL 4.3+ болса — `glDebugMessageCallback` (debug context): драйвер қатені мәтінмен және дәл сәтте айтады.
- RenderDoc сияқты құралмен кадрды түсіріп, текстураның күйі мен mipmap деңгейлерін көру.
- Фрагмент шейдерінде `FragColor = vec4(vTexCoord, 0.0, 1.0)` — UV дұрыс келе ме, мәселе текстурада ма, соны бөлу.

**Қара кубтың басқа себептері:**

1. `glGenerateMipmap` шақырылмаған немесе `glTexImage2D`-ден бұрын шақырылған (MIN-де mipmap тұрақтысы) — 10-black-cube.png.
2. Сурет жүктелмеген (`stbi_load` → NULL, жол қате): `glTexImage2D` шақырылмайды, текстура бос.
3. `ourTexture` униформы мен `glActiveTexture` блогы сәйкес емес (мысалы, uniform = 1, текстура GL_TEXTURE0-де).
4. `glEnableVertexAttribArray(1)` жоқ — `aTexCoord` әрқашан (0, 0), бүкіл бет бір тексельдің түсіне боялады; сол тексель қараңғы болса, куб қара болып көрінеді.
5. Альфасы бар PNG-ге `GL_RGB` (немесе керісінше) — арналар жылжиды, түстер бұзылады/қараяды.

## 5-тапсырма — UV масштабы пернемен

`[` / `]` басылып тұрғанда `uvScale ± 2·dt`, 0.5…8.0 аралығымен шектелген. uvScale = 4 → әр жақта 4×4 (11-uvscale-4.png).

**Шейдерде көбейту мен `vertices[]`-де көбейтудің айырмашылығы:**

| | `vertices[]`-де (`V` пернесі) | шейдерде (`uvScale`) |
|-|-------------------------------|----------------------|
| қашан есептеледі | бір рет, CPU-да; өзгерту үшін VBO-ны қайта жүктеу (`glBufferSubData`) | әр фрагментте GPU-да |
| құны | рендер кезінде нөл | бір фрагментке бір көбейту — іс жүзінде байқалмайды |
| икемділік | барлық объект үшін бірдей, жақтарға әртүрлі мән беруге болады, бірақ өзгерту қымбат | әр draw call-да әртүрлі (мұнда еденге ×40), уақытпен анимацияланады, пернемен лезде |

Жылдамырағы — `vertices[]` (жұмыс алдын ала жасалған), икемдірегі — шейдер. Бір фрагментке бір `vec2 * float`
қазіргі GPU үшін тегін дерлік, сондықтан өзгеретін нәрселер (масштаб, жылжу, анимация) үшін шейдер жақсы.
